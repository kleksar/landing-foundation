# Контекст проекта

## Проект и задача

- Режим: `foundation` — разработка общего шаблона, клиентского заказа здесь нет.
- Источник задачи: согласованный план в [дорожной карте](docs/roadmap.md).
- Цель: один независимо оформленный статический сайт на копию репозитория;
  агент выполняет техническую работу и сохраняет контекст между сессиями.

## Подтверждённые решения

- Bun / React / Vite / TypeScript; один сайт, без обязательного backend.
- Работа небольшими этапами, TDD для изменений поведения, независимое ревью.
- Этап 2.2 принят: 57 тестов, чистая установка, dev и preview проверены.
- Демонстрационные тексты, оранжевый акцент и `example.com` относятся только к starter.
  Это не требования или домен будущего клиента.

## Материалы и ограничения

- Требования демонстрации: [SITE_SPEC.md](SITE_SPEC.md); её оформление: [DESIGN.md](DESIGN.md).
- Клиентские загрузки в этой сессии не включаются в общий шаблон и примеры.
- Файлы и команды доступны в текущей среде. В новой сессии проверить доступный checkout;
  сам URL или архив в старой переписке не доказывает текущий доступ.

## Открытые вопросы

- Блокирующих вопросов для разработки основы нет.
- Хостинг, публикация и проверка подключения навыков в разных средах — отдельные задачи.

## Текущее состояние и следующий шаг

- Завершены 3.1–3.4 (вход, содержание, дизайн, средства) и 4.1 (проба реализации).
- В 4.2 добавлены основной modern headless Chromium и отдельные Chrome Stable / Firefox /
  WebKit проекты. Два новых policy-теста прошли red → green; CLI выбирает 8 / 24 E2E.
- Полный `verify` в 4.2 — exit 1: lint, typecheck, 34 unit, 10 repo и 7 build contracts
  прошли; основной браузер не запустился из-за `socket() Operation not permitted`.
  WebKit также заблокирован отсутствующими OS-библиотеками. Точные результаты совместимости
  и условия запуска записаны в [браузерной приёмке](docs/evaluations/browsers.md).
- Приёмка 4.2 не завершена. Следующий шаг — повторить `bun run verify` и
  `bun run test:compat` в поддерживаемой среде с установленными браузерами/OS-зависимостями.
  Не повторять те же заблокированные установки без изменения окружения. GitHub Actions
  можно проверить после загрузки репозитория; удалённого репозитория сейчас нет.
- Приложение, зависимости и навыки в 4.2 не менялись. Исторические 65 успешных тестов 4.1
  относятся к отдельной учебной копии; последний полностью успешный verify основы — 57 в 3.1.
- Остальные пробы: [реализация](docs/evaluations/implementation.md),
  [intake](docs/evaluations/intake.md), [содержание](docs/evaluations/content.md),
  [дизайн](docs/evaluations/design.md), [инструменты](docs/evaluations/tooling.md).
- Автоподключение навыков и GitHub-коннектор не проверены; пробы читают AGENTS явно.
- Результаты и подробная история: [дорожная карта](docs/roadmap.md).

При начале нового клиентского сайта в отдельной копии агент заменяет эту запись контекстом
клиента и режимом `client`; не переносит факты, оформление или разрешения демонстрации.
